# Account-free test suite implementation plan

Status: endorsed explicitly by both Sol and Opus on 2026-11-04; implemented and locally verified on macOS. Linux/hosted-runner execution remains unverified. This plan builds on the [reliability review](reliability-review.md) and preserves the [testing boundary](../testing.md). Its purpose is reliable Linux SDK coverage and native fixture coverage on an unconfigured Mac, without launching Messages or changing host protections.

## Scope and acceptance

1. **Portable runner and SDK fixtures.** Bound test subprocesses with `BBC_TEST_TIMEOUT_SECONDS` (default 900 seconds), terminate their owned process groups on timeout, and add `--min-tests N` with CI floors at least the current 11 Linux / 19 SDK / 27 bridge / 122 app tests. Test timeout, nonzero exit despite positive output, count floors, absent/current-output fallback bundles and success. Remove redundant SDK build. Publish the Python peer's port atomically, retain bounded synthetic startup diagnostics, parse readiness within five seconds, and confirm bounded child teardown before deleting files. Record binary bodies as base64. Test the full SDK route/mutation table, binary uploads, upload redirect refusal and disconnect after reading a mutation, with exact request counts. Keep loopback restrictions as failures, not skips.

2. **Native fixture reliability.** Let LocalAPIServer accept port zero and report its bound port; use that in fixtures. Bound listener readiness and AVAssetWriter waits. Replace dependent setup force unwraps with throwing guards/XCTUnwrap in media/API fixture tests. Ensure fixture-owned connections/processes stop before temporary stores are removed. Avoid a general-purpose test framework.

3. **Broker ownership and lifecycle.** Inject command/authentication deadlines with unchanged defaults; add shared helper/worker fixtures with explicit request IDs and command counts. Reproduce and fix duplicate pending UUID rejection poisoning the original transaction. Test silent-helper uncertainty, a genuinely expired late result followed by a new successful request, duplicate results, second-helper rejection, capacity rejection preserving existing requests, unauthenticated idle timeout and malformed helper disconnect. Add awaitable broker shutdown with ownership-checked endpoint removal and validate client reply kind using a synthetic broker. Use protocol barriers and bounded reads/watchdogs rather than sleeps as ordering proofs. Do not require every lifecycle test to finish under one second on slow CI.

4. **Native load timing.** Add a bounded load-timeout seam alongside the existing scan timeout, with production defaults unchanged. Use short load deadlines and generous outer watchdogs in synthetic tests; verify existing public entry points retain their defaults. This removes the five-second fixture bottleneck without weakening production timeouts.

5. **Native worker integration.** Extract a request-in/result-out seam used by the existing CLI, with explicit fixture database, endpoint, lock directory and confirmation timing. Use the shared fake bridge and SQLite fixtures for reply or tapback acknowledgement plus exact row, missing/wrong GUID/chat/root/body, invalid acknowledgement GUID, explicit native rejection, unavailable bridge, disconnect after command, held lock and unknown target. Assert zero or exactly one forwarded command and no redispatch during polling. Cover reply as well as tapback if their confirmation paths differ. Keep all resources beneath the fixture root and retain production defaults.

6. **Legacy RPC classification.** Add a request-in/result-out seam and narrow injected text-send actions for startup/permission checks, script execution, lock paths and confirmation timing. Invalid input, held lock, denied permission and startup failure are non-dispatched; exceptions after entering script execution and unconfirmed/ambiguous rows remain uncertain. Test exact single-row success and invalid read parameters. Do not execute AppleScript in tests or broaden downstream retry behavior.

7. **Router lifecycle and receipts.** Test in-flight identical requests executing once, changed payload conflicts, operation ownership, intent-write failure executing zero calls, completed and unresolved operation replay after reopening both key store and router, corrupt/truncated records failing closed, stored permissions, and final-write failure preserving the observed result with replay blocked. Test typing accepted/pending through completion, stop and key-change cancellation with one native invocation. Add a small file adapter only if needed for deterministic failure injection. Verify SDK/server route and observational classification parity through an internal test seam, not a new public API solely for tests.

8. **Integration and evidence.** Update testing/reliability documentation after implementation, raise CI floors to final observed totals, retain bounded failure logs, run clean local suites with named skips, and attempt Linux execution if a usable runtime exists. State unavailable Linux/CI runner evidence honestly; do not invent support for a hosted runner or change signing/packaging merely to satisfy a test. Keep packaging/ABI validation separate from fixture suites.

## Deferred work

Power-loss durability/fsync guarantees, broad portable-core extraction or new crypto dependencies, EmbeddedSession typing-lease extraction, native transfer cancellation/rollback, advanced media handoff ownership refactors, and authenticated idle-worker expiry are separate follow-up proposals. The current iteration targets process-restart/no-replay behavior and fixture reliability; it does not prove private-API compatibility or recipient delivery.

## Implementation approach

After both reviewers endorse this same document, assign bounded, non-overlapping packages to cheaper Sonnet agents at low effort. Implement fixture/broker seams before dependent worker tests. The moderator integrates changes, resolves small findings and verifies the combined suite. No commits, pushes, live messaging, private fixtures, model downloads, HOME overrides, host-protection changes or UI fallback are part of this work.

## Verification result

Clean rebuilds of all three Swift packages on 2026-11-04 executed 24 SDK tests, 29 Objective-C bridge fixture tests, 164 app tests (one intentionally skipped model-staging check) and 16 Python runner tests, with zero failures. The embedded bridge also built for arm64, arm64e and x86_64 with the Mac Catalyst platform. SDK, bridge and app CI floors were raised to these observed totals; the Linux floor remains 11 pending a real Linux run. Linux HTTP test source now contains 16 cases, but source counts are not execution evidence. No Linux daemon was available locally and no hosted CI run was triggered. Existing toolchain/SQLite deployment-target linker warnings remain outside this test-suite change.

All implementation packages used Sonnet at low effort. The moderator corrected integration edge cases in duplicate status IDs, runner fallback/deadline handling and bounded fixture startup. Sol and Opus endorsed the plan before implementation; that endorsement is not a claim that they reviewed the final patch.
